## 2. Critical

**C1. Two different price sets for the same products.**
- Set A (components, and `INSTRUCTIONS.md:47-48`): digital €30–50; canvas 30×30 €69, 40×40 €89, 50×50 €119.
  - `components/PricingTiers.tsx:13, 24-26, 33, 44-46`
  - `components/OrderForm.tsx:79-81`
- Set B (messages files, unused at runtime): digital €9–15; canvas 30×30 €29, 40×40 €39, 50×50 €55.
  - `messages/de.json:36, 41-43, 70-72`
  - `messages/en.json:36, 41-43, 70-72` (same keys as German; line numbers not checked individually, see section 6)
- Plan step 2 says: do not pick one; write both into `docs/price-audit.md` and ask the owner.

**C2. Text is not in the messages files.** Every component hardcodes German and English strings in `isDE ? … : …` ternaries (for example `components/Hero.tsx:19-37`, `components/Header.tsx:43-53`). This breaks the rule "all visible text lives in messages/*.json". It also means the existing translations are already out of sync with the UI.

**C3. Impressum and Datenschutz are missing.** Required in Germany. The footer (`components/Footer.tsx`) has no links to them. Placeholder pages are needed (Step 11).

**C4. Test suite does not exist.** `jest` is configured but nothing is tested. The project standard (Standards section) asks for Vitest and React Testing Library, plus one Playwright spec. The repo uses Jest, so this is a decision to make in Step 1 or later (keep Jest, or switch to Vitest).

**C5. The mobile menu button does nothing.** `components/Header.tsx:66-70` renders a hamburger `<button>` with no `onClick` and no `aria-label`. On phones (below `md`, 768px) the navigation is not reachable at all. The main nav (`Header.tsx:42`) is `hidden md:flex`.

## 3. Important

**I1. Lint errors (blocks the "zero warnings" standard).**
- `i18n.ts:7` `as any` (error, no comment)
- `scripts/init-db.js:1-2` `require()` imports (errors)
- `components/OrderInfo.tsx:94` unused `idx` (warning)
- `components/PricingTiers.tsx:4` unused `CardDescription` (warning)
- Further errors and warnings in the full eslint output (15 problems in total).

**I2. Upload limit silently ignored.** `components/OrderForm.tsx:45-53`: a file over 15 MB is dropped with no message. The user sees nothing happen. The plan asks for a clear message before submit (Step 9).

**I3. Hardcoded English alt texts.** `components/Hero.tsx:61` ("Ultrasound artwork example"), `components/Gallery.tsx:29, 41, 56` ("Full size image", "... example 1/2") are English in both languages. Plan: alt text in both languages.

**I4. Gallery close button has no accessible name.** `components/Gallery.tsx:61-64`: `✕` button without `aria-label`. The lightbox has no keyboard close or focus handling.

**I5. Formal and informal German mixed.** The standard is "du" everywhere.
- Formal ("Sie"): `components/FAQ.tsx:17` ("Welche Bildformate akzeptieren Sie?"), `app/[locale]/order/page.tsx:20` ("Hier können Sie …").
- Informal ("du"): `components/Hero.tsx`, `components/HowItWorks.tsx`, `components/ContactSection.tsx`, `components/OrderInfo.tsx`.

**I6. Contrast of the main button likely fails.** `Hero.tsx:45` and `ContactSection.tsx:33` (`OrderForm.tsx:395` uses `pink-600`): white text on `bg-pink-500` (#ec4899). My own calculation: about **3.5:1**, below the 4.5:1 minimum. `pink-600` (#db2777) on white is about **4.6:1**, which passes. This needs the real check in Step 3.

**I7. Heading structure.** `Header.tsx:21-33` shows the logo name in a `<span>`, not a heading. Hero `h1` is OK. Section `h2`s are used everywhere. `FAQ.tsx:70-72` puts an `h3` inside a `<button>`, which is valid but awkward for screen readers.

**I8. Anchor links without a sticky bar.** `Header.tsx:49, 52` and `Hero.tsx:50` jump to `#pricing` and `#contact`. There is no sticky bar and no `scroll-margin-top` (planned in Step 4a).

**I9. Language switch loses the current page.** `Header.tsx:18-21` replaces only the locale prefix in `window.location.href`. This works, but it is a full page reload. `app/page.tsx:3` redirects `/` to `/en`, although `defaultLocale` is `de` (`middleware.ts:6`). The two must agree.

**I10. Two order-form endpoints and no shipping validation.** `app/api/orders/route.ts` takes `product` and `canvasSize` as plain strings from the client. Prices are not validated server-side. Relevant after Step 2.

**I11. Gallery images have no `sizes` attribute.** `components/Gallery.tsx:27-30, 39-42` use `fill` without `sizes`. Browsers may download a larger image than needed. Plan Step 8.

**I12. Copyright year is hardcoded.** `components/Footer.tsx:11-12`: "© 2024". Should be dynamic.

**I13. Email address hardcoded in three places.** `components/ContactSection.tsx:28`, `components/Footer.tsx:29-30`, and the `mailto:` in the same file. Should come from one config value (Step 11).

**I14. Dead code and leftover pages.** `app/[locale]/test/page.tsx` (debug page, reachable in production), `components/ui/tabs.tsx` (unused), `public/*.svg` (Next.js starter files, unused), `components/ui/button.tsx` (not used anywhere, so the Button step will replace or reuse it).

**I15. Fonts from Google.** `app/layout.tsx:2-3`. See section 1. Plan Step 1: self-hosted files, `display: swap`, same families.

**I16. No `Organization` or `Product` structured data, no `hreflang`, no `canonical`, no `sitemap.ts` or `robots.ts`.** Plan Step 11.

**I17. Two tiers of duplication for prices and sizes.** Sizes and prices are typed in `PricingTiers.tsx` (twice, once per language), `OrderForm.tsx:79-81` and `messages/*.json`. Plan Step 2.

## 4. Nice to have

- `components/Footer.tsx:22` logo link is `href="/"` (not locale aware); `Header.tsx:15` uses `isDE ? '/de' : '/en'`. Use one helper.
- `components/Header.tsx`: plain `<a>` tags instead of `next/link`. Client-side navigation is lost. Fine for now.
- `app/layout.tsx:33` uses `suppressHydrationWarning` on `<html>`. Probably unnecessary.

- `README.md`, `INSTRUCTIONS.md`, `PROJECT_STATUS.md`, `TEST_GUIDE.md`, and `.vercel/` are in the root. Documentation consolidation is optional.
- `app/api/orders/route.ts`: email HTML is built with string interpolation of user input (`${orderData.name}`, `${orderData.specialRequests}` at lines ~123-138). This is an HTML injection risk in the owner's own mailbox. Escape it.
- `TEST_GUIDE.md:153` says "minimum 48x48px" for touch targets. The plan standard is 44px. Keep one number.

### Conflicts between the guide and the upgrade plan

These need your decision before Step 1. I have not resolved them.

1. **Where text lives:** the guide says `content/` for all text. The upgrade plan says `messages/de.json` and `messages/en.json` (next-intl). Both can coexist (next-intl messages for UI strings, `content/` for facts, dates and prices), but one must be the rule for each kind of text.
2. **Branch names:** the guide uses `feat/`, `fix/`, `chore/`, `docs/`, `test/`. The upgrade plan says `feature/salon77-patterns`. The branch already exists under the plan name.
3. **Commit types:** the guide adds `style(scope):` and uses scopes. The plan lists `feat:`, `fix:`, `refactor:`, `docs:`, `test:`, `chore:` without scopes.
4. **Playwright scope:** the guide asks for all browsers and mobile profiles on `main`. The plan asks for one spec file, Chromium only, two viewports. The plan is stricter; I would follow the plan for Step 12 and add the guide's CI matrix later.
5. **Security headers and CSP:** the guide sets a full CSP. The plan does not mention it. This goes in Step 11 or as a new step, which needs your approval.
6. **Lighthouse CI:** the plan says "no Lighthouse unless I ask". The guide requires it. Plan wins unless you change it.

## 8. Decisions (owner, 2026-11-11)

Recorded from the owner's reply. These replace the open questions above.

1. **Text lives in `content/`** (Salon77 rule). Components take props. No visible text is typed in components or in `messages/*.json`. The existing `messages/*.json` files are to be migrated into `content/` in Step 1.
2. **Branch name is `feat/salon77-patterns`** (Salon77 rule). Renamed locally from `feature/salon77-patterns`. It was never pushed, so nothing remote changed. Commits use Conventional Commits with scopes, for example `feat(hero): ...`.
3. **Prices: one consistent set, and the price question is not blocking.** The set used is the one visitors see today on the live components and in `INSTRUCTIONS.md`: digital €30–50, canvas 30×30 €69, 40×40 €89, 50×50 €119. The `messages/*.json` set (€9–15, €29/39/55) is dropped. Step 2 creates the single data file from this set. The owner can change the numbers later in that one file.

Open items still to confirm: Playwright and Lighthouse scope (guide vs plan), and the CSP step.
